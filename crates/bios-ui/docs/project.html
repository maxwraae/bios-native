A project holds constructs. It is a folder on your computer, wherever you keep it, and Bios opens folders the way a code editor does: any folder of sequence files opens as a project, and the ones you opened are kept in a list.

The grid

Opening Bios puts you on the projects grid: the folders you opened lately. Each card draws a real map of what is inside rather than an icon, along with how many constructs it holds, when you last touched it and where its folder is, so you can find the right one by sight.

There are three ways to start:

  • Open folder. Any folder opens as it is, even one of plain GenBank, FASTA or SnapGene files from your Downloads. Nothing is written into it until you change something; then it becomes a Bios project, with its history kept beside its files.
  • New project. Choose where to make it and what to call it.
  • Drop a file on the grid. A project is made around it.

Projects can be pinned, reordered by dragging, searched and renamed (the folder is renamed where it is). Removing one from the list leaves its folder alone; deleting moves the folder to the Trash, and asks first, in the card itself.

Constructs

Inside a project, the constructs are listed in the rail on the left. Several can be open at once, each with its own undo history and its own save queue, so an edit in one cannot disturb another.

Per construct, from the rail:

  • Rename it.
  • Clone it, which opens the copy beside the original.
  • Delete it, confirmed in the row.
  • Focus it, which is the one worth understanding. See below.

The + on the CONSTRUCTS header makes a new blank one. Dropping a plasmid file anywhere over the working area adds it to the project you are in.

Moving between them

  • Ctrl Tab and Ctrl Shift Tab step through the open constructs.
  • Cmd 1 to Cmd 9 jump to one directly.
  • Cmd W closes the one in front.

When you come back later, the constructs you had open are put back.

Which construct the assistant is looking at

This is the part that catches people out. Having several constructs open means the assistant needs to know which one you mean, and it does not guess from whichever tab happens to be in front. The construct it works on is the one you have set as the focus, from the rail.

If the assistant answers about a different construct than the one you are staring at, this is almost always why.

Saving

Editing saves as you go and there is no Save button. Cmd S flushes a pending save straight away rather than waiting the couple of seconds it would take on its own.

One caveat worth knowing: after the assistant makes an edit you accepted, the construct is brought back into line when the app next saves it. If you have just accepted a proposal and are about to close the tab, press Cmd S first.
